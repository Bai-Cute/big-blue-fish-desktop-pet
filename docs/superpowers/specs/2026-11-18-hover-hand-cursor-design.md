# 悬停与按下的手掌光标 · 设计

日期：2026-11-18
状态：已实现

## 目标

鼠标停到鱼身上时显示张开的手掌，按下左键或拖拽时换成收拢的手掌，松开恢复。提示"这里可以点、可以拖"。

Windows 只自带一种"手"（`Cursors.Hand`，食指指向），没有手掌光标，所以两种状态都必须作为素材随程序分发。

## 行为

- 指针落在鱼身不透明像素上时显示张开的手掌。
- 左键按下、拖拽过程中显示收拢的手掌。
- 松开左键、丢失鼠标捕获、窗口被隐藏时恢复张开的手掌。
- 鱼四周的透明边距、气泡、右键菜单、聊天窗口、设置窗口的光标行为不变。
- 双击打开输入框的路径不进入按下状态，避免光标闪一下。

## 素材

图标来自 Lucide 的 `hand`（全掌）与 `hand-grab`（收拢），ISC 许可，版权与许可文本见 `licenses/Lucide-ISC.txt`，来源说明见 `THIRD-PARTY.md`。两个 SVG 原样保存在 `Res/Cursor`，便于将来重新生成。

离线处理流程：

1. 用系统自带 Edge 无头模式把 SVG 渲染成 256×256（黑描边、白底），再按亮度取反得到 alpha 遮罩，避免依赖额外的渲染库。
2. 两个 SVG 的轮廓都是闭合的，因此对内部做洪水填充得到白色掌体，保留深色描边。纯描边版本在深色桌面上看不见，白填充是光标惯例。
3. 合成 32 与 48 两种尺寸，写成 32 位 DIB 光标条目（带 alpha 与 AND 遮罩），得到 `Palm.cur` 与 `PalmGrab.cur`。

热点取张开手掌掌体的质心（约画布 55%, 57%），**两个状态共用同一热点**——否则按下那一瞬间指针会跳一下。

## 实现

`CompanionSpriteImage` 静态加载两个光标（pack URI 读资源，失败回退 `Cursors.Hand`），构造函数使用张开态；新增 `SetPressed(bool)` 在两者之间切换。

`CompanionWindow` 在鼠标按下、松开、丢失捕获、会话恢复四处调用 `SetSpritePressed`，切到 `videoImage` 上。

按下时还必须同时设置**窗口自身**的光标：拖拽把鼠标捕获给了窗口，WPF 在捕获状态下按捕获元素解析指针，而窗口原本没有光标，于是回落到箭头——只设图像光标时，按下会看到指针从手掌变回箭头。松开时把窗口光标置回 `null`，让命中元素的图像光标重新生效。

切换光标必须调用 `Mouse.UpdateCursor()`：WPF 只在鼠标移动时重新求值指针形状，否则按住不动时图案会停在张开态。

命中判定沿用该类已有的 `HitTestCore`（按帧像素 alpha ≥ 8），所以两种光标都只出现在鱼身可见部分。

## 验证

`AnimationUiVerification` 的 `--cursor` 模式在真实窗口上断言：

- 生效光标不是 `Cursors.Hand`（证明自定义素材加载成功，没有走回退）
- 透明边距仍然不接收命中，鱼身仍然可点
- 调用真实的按下处理器后光标变成收拢态
- 调用真实的松开处理器后恢复张开态

按下/松开通过反射调用窗口自己的处理器，走真实的分支逻辑。合成 `PreviewMouseLeftButtonDown` 事件不行：那是直接事件，不会从窗口隧道到图像。

## 不做

- 不增加设置开关。
- 不做按下后的第三个状态（例如握紧抖动）。
- 不为 macOS / Linux 引入等价改动：该控件属于 Windows 专属的 `BigBlueFish.Windows` 项目。
